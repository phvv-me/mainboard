## What changed, by issue

1. The delimiter. A verb that hands a command on (`run`, `job submit`, `shell`, `proc timeout`,
   `help`, `list`, `tree`) gets its `--` at the first token that is not its own. The rule used
   to give up whenever the line held a `--` anywhere, so a wrapped command's own `--` sent its
   flags to the parser. Now a later `--` travels with the command. One spelling keeps the old
   reading because it works today and losing it would fail on the host minutes later: this
   verb's own options written after the target and ended by the caller (`job submit x.py::t
   --on gold -- --fresh a`). `proc timeout` also learned that its seconds come before the
   command, so `proc timeout 30 -- cmd` and `proc timeout 30 cmd -- args` both pass through
   verbatim. The `job submit` docstring spelled a lane as `path::test --on a,b --split model`,
   which hands `--on` to the job; it now puts the options first.
2. `dispatch.commandline.joined` is where every command bound for a host or a shell line is
   built (`job submit`, `run --on`, lanes). It now refuses an argument carrying the root of an
   MSYS shell on PATH (every `cygpath` on PATH is asked for its `/`, since under `mb run` the
   environment's own MSYS tools lead PATH ahead of Git's). The refusal shows what was typed
   (`/home/crimson/cache/y`) and names `MSYS_NO_PATHCONV=1` (and `MSYS2_ARG_CONV_EXCL='*'` for
   MSYS2). With the switch set nothing is refused. Refused rather than restored: a rewritten
   path list (`/a:/b` becomes `C:\...\a;C:\...\b`) cannot be restored with certainty.
3. Setup installs the mirror's own environment (what `run --on`, `shell --on` and every
   dispatch's preflight enter). A job activates a separate copy addressed by the lock's content
   (`<root>/.mainboard/prefixes/<env>/<digest>`), which `provide` builds at the first dispatch
   of each lock. The stage now reads `installing tl in crimson's mirror from the shipped lock`
   and setup ends with `crimson runs commands in tl; a job activates its own pinned copy, which
   the first dispatch of each lock builds there`. The `host setup --help` text says the same.
7. Four changes. A state probe knocks once instead of four times with backoff (its callers
   either report the host quiet or ask again on their own cadence). A listing no longer knocks
   on a host the settling pass just found quiet. One process leaves a quiet host alone for 30
   seconds, so a wait on crimson's job no longer pays for gold on every five-second pass. And
   an unreachable host is a sentence, not a traceback (`mb run --on gold -- true` printed forty
   lines). Messages: a live row on a quiet host says `gold not heard from; last recorded ...`
   in `cause`; the note says how many live runs the host holds and that `mb job cancel
   <handle>` gives one up without stopping it there; a wait says once which host is silent; a
   host the manifest dropped names the exact commands (`mb job cancel 1 --on vast-rtx-4090`).
   `job cancel` on a host that does not answer now settles the run with a warning that nothing
   was stopped there (it used to end as a traceback with the run half settled).
8. `Repo.unreadable` runs the status a bare `git status` runs, owned submodules excluded so
   each repository answers for itself. `git status` gained a `broken` column (printed only
   when a row has one) and `git check` a `submodule` warning, both carrying git's own words.
9. `state/evidence.py` and `diagnostics.py` wrote text without `newline=` (CRLF on Windows).
   `host offers` died as a traceback when one cloud's catalog answered 502 (Vultr); it now asks
   each catalog alone after such a failure and names the silent one.

## Designs left as designs

- Build the job's environment at setup (issue 3, the real fix). After `Bootstrap.environment`,
  run `mb provide <env> --expect <digest>` on the host, the digest being the one
  `Board.addressed` pins at dispatch, so the first submit finds its prefix built. It needs one
  check on an idle host first: that the digest a host computes from its mirror after `install`
  equals the center's (the dispatch builds from the pinned snapshot, never from the mirror).
  About 25 lines and a test with a fake shell; one to two hours with the live check.
- The dispatch's `built <env> on <host>` line prints whether or not anything was built. Probe
  the prefix stamp before `provide` and say `building` or `found`. Ten lines; it sits on the
  path of every submit, so it wants one live dispatch to confirm.
- Landing closure (6c). `Landing.equip` mirrors `plan.profile.sync`, narrowed only by
  `[envs.<env>] sources` and `[hosts.vast.sync] exclude`. For a job spelled by file the scope
  should be what installs (the manifest, the lock, every local project's `pyproject.toml`, the
  source of the workspace packages the environment installs: `Board.imports`) plus the closure
  listing, needs and pins, which already ship by name. Half a day with a scope test and one
  rental to confirm.
- A Task Scheduler settler for Windows. `durable.Settler` is the seam: `schtasks /Create /SC
  MINUTE /MO 20` running `mb job monitor --json` in the workspace, state read from `schtasks
  /Query /XML` (not localized), removed with `/Delete`. Two to three hours with a fake
  `schtasks` in tests. Until then a task can be created by hand.
- `job list` asks each answering host twice (the settling pass, then the listing) and a third
  time for the pulse; reusing the settling pass's states would save a connection per live host
  (about 4 s each through the cvlab jump). One hour.
- A cancel the host never heard. Record it as owed, so the first sweep that reaches the host
  stops the job there. One to two hours.
